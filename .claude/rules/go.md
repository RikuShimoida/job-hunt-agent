## Go コーディング規約

### エラーハンドリング
- エラーは握り潰さない。`_ = err` は禁止
- ラップは `fmt.Errorf("...: %w", err)` を使い、呼び出し元で `errors.Is` / `errors.As` で判別できる状態を保つ
- センチネルエラーは `var ErrXxx = errors.New("...")` としてパッケージレベルに定義する
- ライブラリコードで `panic` しない。`panic` はプログラマのバグ（不変条件違反）に限る
- エラーメッセージは小文字始まり・句読点なし（`fmt.Errorf("failed to open config: %w", err)`）

### context
- I/O・ネットワーク・長時間処理を行う関数は第1引数に `ctx context.Context` を取る
- `context.Background()` は `main` / テスト / 最上位のエントリポイントでのみ生成する
- 構造体に `context.Context` をフィールドとして持たせない

### 並行処理
- goroutine は必ず終了条件を持たせる（リークさせない）。`ctx` のキャンセルで抜けられるようにする
- 共有状態は `sync.Mutex` かチャネルで保護する。競合が疑われる変更では `go test -race ./...` を実行する

### 設計
- インターフェースは**利用側パッケージ**で定義する（提供側で先に抽象化しない）
- 小さいインターフェース（1〜3メソッド）を基本とする
- 公開する識別子は最小限に。まず小文字（unexported）で書き、必要になってから公開する
- 構造体の初期化は必要なら `NewXxx()` コンストラクタを用意し、ゼロ値で使えるならそれを優先する

### 命名
- パッケージ名は小文字・単数形・アンダースコアなし。`util` / `common` / `helper` のような無意味な名前は禁止
- レシーバ名は 1〜2 文字で型全体を通して統一する
- getter に `Get` プレフィックスを付けない（`u.Name()` であって `u.GetName()` ではない）

### 依存関係
- 依存追加は必要最小限。標準ライブラリで足りるものは標準ライブラリを使う
- 依存を追加したら `go mod tidy` を実行し、`go.sum` の差分も同一コミットに含める

### 品質チェック（順序厳守）
1. `gofmt -w .`
2. `go vet ./...`
3. `golangci-lint run`（エラーがあれば修正し、再度 `gofmt` を実行）
4. `go test ./...`
