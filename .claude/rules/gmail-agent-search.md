## Gmail で案件を探すときの参照ルール

claude.ai の Gmail コネクタ経由で案件を探す（応募返信メールの下書き作成などのワークフロー）とき、
**無造作に Gmail を検索してはならない**。転職サイトのスカウトやアルバイト求人など、利用者が登録して
いないエージェントの求人メールを拾うと、案件源が汚れる。

### 手順

1. **[docs/registered-agents.md](../../docs/registered-agents.md) を必ず参照する。** これが利用者の
   登録エージェント一覧であり、探索対象の唯一の正。
2. **「案件メールが届く」列が ○ のエージェントに絞って探す。** 送信元アドレスが判明しているものは
   そのアドレスで絞り込む（例: フォスターフリーランス → `careers.desk.haishin@foster-net.co.jp`）。
3. **拾った案件のソース URL／送信元が登録エージェント由来かを検証する。** 一覧に載る
   エージェントの送信元・ドメインと突き合わせる。

### 未登録・対応不明な送信元の扱い

- **登録エージェントと対応が取れない送信元のメールは、案件候補から外す。** 無造作に拾わないことを
  優先する（登録外の求人を混ぜない）。判断に迷うものは候補へ入れず、必要なら利用者へ確認する。
- **送信元アドレスが「未取得」のエージェント**（一覧でアドレス未確定のもの）は、エージェント名や
  本文の文面での一致を手がかりに参照してよい。ただし機械的なアドレス照合ができない旨を添え、
  誤って登録外を通さないよう慎重に扱う。

### 前提

- このルールは **Claude の手動ワークフロー向け**。job-hunt-agent（Go）の収集対象は
  `config/sources.yaml` の `senders` ホワイトリストが正であり、本ルールとは別レイヤー。
- 送信元アドレスが実メールで新たに確定したら、[docs/registered-agents.md](../../docs/registered-agents.md)
  の「未取得」を実アドレスへ更新する（推測で埋めない）。
