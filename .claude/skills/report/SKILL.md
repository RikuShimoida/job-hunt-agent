## 作業完了時の品質チェック（順序厳守）

作業完了の報告前に、以下を **必ずこの順序で** 実行すること。

### 1. フォーマットを実行する

- `gofmt -w .`

### 2. 静的解析を実行する

- `go vet ./...`

### 3. lint を実行し、エラーがあれば必ず修正する

- `golangci-lint run`
- 修正が発生した場合は再度フォーマットを実行する

### 4. テストを実行する

- `go test ./...`
- 並行処理に触れた変更なら `go test -race ./...` も実行する
- 受入条件を満たしていることを確認できない場合は作業完了としてはならない

### 禁止事項

- 受入確認 **前に** コミット・プッシュ・PR 作成を行うこと
- フォーマットや lint 修正 **後に** コミットせずに作業を終了すること
- テストが落ちたまま「完了」と報告すること

## 報告義務

品質チェック完了後、必ず以下を報告すること。

1. **何を修正したのか**
2. **なぜその修正が必要だったのか**
3. **どのファイルを変更したのか**
4. **受入条件をどのように満たしたか**（どのテストで検証したか）
