## PRコードレビュー

引数: `$ARGUMENTS`（PR番号。例: 123）

### 手順

#### 1. PR情報の取得

```bash
gh pr view $ARGUMENTS
gh pr diff $ARGUMENTS
```

#### 2. コードレビューの実施

以下の観点でレビューする（このリストがレビュー観点の**単一の正**）:

- **設計整合性**: 設計ドキュメント（README.md / docs/architecture.md）・既存パッケージ構成との整合。パッケージ間の循環依存
- **エラーハンドリング**: 握り潰し（`_ = err`）、`%w` ラップ漏れ、`errors.Is`/`errors.As` で判別可能か、境界値・異常系の考慮
- **並行処理**: goroutine リーク（終了条件の有無）、データ競合、`context` の伝播漏れ・キャンセル未対応
- **セキュリティ**: インジェクション、認証・認可の漏れ、機密情報のログ出力・エラーメッセージ露出
- **パフォーマンス**: N+1、不要なアロケーション、不要な同期、無駄な I/O
- **コード品質**: 命名、関心の分離、重複、公開範囲の過剰さ（不要に exported になっていないか）
- **テスト**: 網羅性・妥当性。意味のないアサーション、テストのためのハードコードが無いか

**重要**: コードの修正は一切行わない。レビューコメントの作成のみ。

#### 3. レビュー結果のPRコメント投稿

レビュー結果を以下のフォーマットでPRにコメントする:

```bash
gh pr comment $ARGUMENTS --body "$(cat <<'EOF'
## 🔍 コードレビュー（by system-architect）

### 総合評価
<!-- Good / Needs Discussion / Request Changes のいずれか -->

### 良い点
<!-- 設計やコードで良かった点を箇条書き -->

### 指摘事項
<!-- 以下のフォーマットで指摘 -->
<!-- - **[重要度: High/Medium/Low]** 対象ファイル:行番号 — 指摘内容 -->

### 提案・改善案
<!-- 必須ではないが、より良くなる提案を箇条書き -->

---
🤖 This review was generated by Claude Code (system-architect agent)
EOF
)"
```

#### 4. ユーザーへの報告

PRにコメントを投稿した旨をユーザーに報告する:
- PR番号とURL
- 指摘事項の概要（件数と重要度の内訳）
